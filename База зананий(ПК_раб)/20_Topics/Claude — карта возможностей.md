# Claude — карта возможностей

Карточка выбора инструментов экосистемы Claude: что использовать для результата в чате, повторяемой инструкции, доступа к данным, работы с репозиторием и автоматизации процессов.

> [!summary] Claude как рабочая система
> **Artifacts** создают результат → **Skills** закрепляют способ работы → **Connectors** дают доступ к внешнему миру → **Claude Code** работает с кодовой базой → **MCP** стандартизирует подключение инструментов → **Projects** удерживают контекст → **Automation** запускает процесс по событию или расписанию.

## Быстрый выбор

| Потребность | Использовать |
|---|---|
| Создать интерактивный документ, таблицу, диаграмму или прототип | Artifacts |
| Повторять один workflow с одинаковыми правилами | Skills |
| Читать или изменять данные конкретного приложения | Connectors |
| Работать с репозиторием, тестами и терминалом | Claude Code |
| Подключить собственный инструмент по открытому протоколу | MCP |
| Сохранить общий контекст, файлы и инструкции по теме | Projects |
| Запускать процесс по времени, событию или условию | Automation |

Доступность функций и названия тарифов меняются. Перед внедрением проверять текущие возможности своего аккаунта и организации.

## Artifacts

Artifacts — создаваемый Claude результат, который можно просматривать и дорабатывать отдельно от текста диалога.

Подходят для:

- документов и отчётов;
- таблиц и аналитических панелей;
- диаграмм и блок-схем;
- HTML-прототипов и небольших web-инструментов;
- презентационных материалов;
- кода, который удобно редактировать отдельно.

Рабочий процесс:

```text
сформулировать задачу
  → получить artifact
    → уточнить структуру и содержание
      → проверить факты, расчёты и поведение
        → экспортировать или опубликовать разрешённым способом
```

Artifact — это форма результата, а не гарантия качества. Код нужно запускать, данные — валидировать, ссылки и выводы — проверять.

## Skills

Skill — переиспользуемая инструкция, workflow и набор ресурсов, объясняющий Claude, как выполнять определённый класс задач.

Хороший skill определяет:

- точный триггер: когда его применять;
- область ответственности и ограничения;
- последовательность действий;
- необходимые входные данные;
- формат результата;
- критерии готовности и проверки;
- scripts, references и templates, если они действительно нужны.

Примеры:

- редакционный стандарт;
- code review;
- онбординг сотрудника;
- подготовка отчёта;
- юридический или маркетинговый шаблон;
- анализ данных по принятой методике.

Чем конкретнее skill, тем стабильнее результат. Большой универсальный skill хуже нескольких узких процессов с ясными границами.

## Connectors

Connector связывает Claude с внешним приложением или источником данных: например, Google Drive, Gmail, Slack, Notion, CRM, календарём, web search или базой данных.

В зависимости от возможностей connector может:

- искать и читать актуальные данные;
- создавать и изменять объекты;
- сохранять результат обратно;
- выполнять действия в контексте учётной записи.

> [!warning] Граница безопасности
> Чтение данных не равно разрешению на отправку, публикацию, удаление или изменение прав. Для внешних действий нужны минимальные разрешения и явное подтверждение на момент действия.

## Claude Code

Claude Code — агентная среда для работы с кодовой базой через терминал или IDE.

Типичные задачи:

- исследовать repository и объяснять код;
- реализовывать feature и refactoring;
- писать и запускать тесты;
- находить и исправлять ошибки;
- изменять несколько связанных файлов;
- запускать команды проекта;
- проводить code review;
- диагностировать CI и производительность;
- проверять базовые security-паттерны.

Примеры команд из карточки-источника:

```text
/explain    объяснить код
/refactor   предложить или выполнить рефакторинг
/test       написать или запустить тесты
/fix        исправить ошибку
/doc        создать документацию
/review     проверить изменения
/optimize   исследовать производительность
/security   проверить риски безопасности
```

Конкретный набор slash-команд зависит от конфигурации. Команда должна иметь ясную область, способ проверки и ограничения внешних действий.

Подробная организация репозитория: [[Claude Code — структура AI-assisted проекта]].

## MCP

Model Context Protocol — открытый протокол подключения AI-приложения к инструментам и данным через стандартизированный сервер.

```text
Claude / AI host
        ↓ MCP
MCP server
        ↓
API · database · filesystem · internal service
```

MCP полезен, когда:

- нужен собственный connector;
- один tool server должны использовать разные AI-клиенты;
- требуется явное описание tools/resources/prompts;
- доступ нужно ограничить и наблюдать на отдельной границе.

MCP не делает интеграцию автоматически безопасной. Проверять authentication, authorization, input validation, audit log, rate limits и минимальный scope.

## Projects

Project объединяет долговечный контекст по одной области:

- инструкции и правила;
- файлы и базу знаний;
- историю и рабочие материалы;
- цель и ограничения;
- связанные skills и connectors.

Проект полезен, если одна тема продолжается между сессиями: продукт, исследование, редакционный процесс или рабочая функция.

Не хранить в project секреты и нерелевантный массив данных. Постоянный контекст нужно периодически очищать от устаревших версий и противоречий.

## Automation

Automation запускает подготовленный workflow без ручного повторения каждого шага.

Основные элементы:

```text
trigger → inputs → actions → conditions → outputs → notification
```

Примеры:

- ежедневный обзор входящих сообщений;
- еженедельный отчёт по метрикам;
- обработка нового документа;
- мониторинг изменения источника;
- подготовка черновика уведомления;
- классификация и маршрутизация обращений.

Автоматизация должна быть:

- идемпотентной или защищённой от повторного запуска;
- наблюдаемой: статус, ошибки, длительность;
- ограниченной по времени, стоимости и числу действий;
- безопасной при частично выполненном процессе;
- отделяющей создание черновика от внешней отправки.

## Connectors и MCP: различие

| Connector | MCP |
|---|---|
| Готовая интеграция с конкретным приложением | Протокол для создания и подключения интеграций |
| Быстрое подключение поддерживаемого сервиса | Гибкость для внутренних и нестандартных систем |
| Возможности определены поставщиком connector | Возможности определяет разработчик MCP server |
| Обычно меньше инфраструктурной работы | Нужны разработка, hosting, auth и сопровождение |

Connector может быть реализован через MCP, но для пользователя важнее не внутренняя технология, а доступные действия и разрешения.

## Skills и Projects: различие

| Skill | Project |
|---|---|
| Описывает **как выполнять** повторяемую задачу | Хранит **контекст конкретной области** |
| Может применяться в разных проектах | Обычно связан с одной темой или командой |
| Содержит workflow и критерии результата | Содержит знания, файлы и локальные правила |

Практичная комбинация: Project даёт контекст, Skill — процесс, Connector — данные, Artifact — результат.

## Лестница внедрения

1. **Разовая задача:** начать с обычного диалога и проверяемого результата.
2. **Нужен отдельный результат:** оформить Artifact.
3. **Процесс повторяется:** вынести правила в Skill.
4. **Тема продолжается:** создать Project с ограниченным контекстом.
5. **Нужны актуальные данные:** подключить Connector с минимальными правами.
6. **Нужна собственная интеграция:** спроектировать MCP server.
7. **Нужен автономный запуск:** добавить Automation, мониторинг и подтверждение внешних действий.
8. **Работа с repository:** использовать Claude Code и project-level инструкции.

## Мощные комбинации

### Исследование

```text
Project context + web/data connector + research skill
  → проверяемый отчёт-artifact
```

### Контент-процесс

```text
brief → brand skill → artifact → review → approved publishing connector
```

### Разработка

```text
Claude Code + project instructions + MCP tools
  → code → tests → review → human-approved delivery
```

### Операционный отчёт

```text
scheduled automation → connector data → reporting skill
  → draft report → validation → notification
```

## Карточка безопасности

- [ ] Подключены только нужные connectors и MCP servers.
- [ ] Разрешения следуют принципу минимальных привилегий.
- [ ] Секреты не помещаются в project files, skills и prompts.
- [ ] Недоверенный документ не может переопределить системные правила.
- [ ] Отправка, публикация, удаление и изменение доступа подтверждаются отдельно.
- [ ] Automation имеет лимиты и не повторяет внешнее действие бесконечно.
- [ ] Claude Code работает только в разрешённой области repository.
- [ ] Результат проверяется тестом, источником, расчётом или человеком.
- [ ] Есть audit trail для важных действий и интеграций.

## Формула выбора

```text
контекст
  + повторяемый процесс
  + разрешённые инструменты
  + проверка результата
  + управляемый запуск
  = рабочая AI-система
```
