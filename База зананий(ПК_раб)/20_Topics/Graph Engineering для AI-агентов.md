# Graph Engineering для AI-агентов

Graph Engineering превращает последовательный agent loop в явный граф: действия и сущности становятся узлами, переходы — типизированными рёбрами, а состояние — общим контролируемым контекстом.

## Когда граф оправдан

- Есть три и более действительно независимые проверки или ветви.
- Разные ошибки должны возвращать управление в разные узлы, а не перезапускать весь цикл.
- Нужно параллельное выполнение с последующим синтезом.
- Система использует multi-hop reasoning и должна объяснять, почему сущности связаны.
- Важны трассировка каждого узла, бюджет повторов и явные termination rules.

Для простой задачи с низкой конкуренцией обычный loop дешевле и понятнее.

## Пять этапов перехода

1. **Audit:** инвентаризировать loops, retries, wall-clock time и token cost.
2. **Identify:** найти независимые работы и реальные точки concurrency.
3. **Design:** начать с 3–5 узлов и определить каждый маршрут.
4. **Implement:** включить async execution и зафиксировать baseline времени и стоимости.
5. **Type:** добавить семантические типы рёбер для multi-hop reasoning.

## Типизированные рёбра

| Тип | Смысл |
|---|---|
| `SUPERSEDES` | новая сущность заменяет старую |
| `DEPENDS_ON` | выполнение требует другой сущности |
| `DECIDED_BY` | решение объясняется источником или правилом |
| `CAUSED` | событие вызвало другое событие |
| `IMPLEMENTS` | компонент реализует контракт |
| `REFERENCES` | сущность ссылается на контекст |

## Метрики

- wall-clock time и стоимость успешного завершения;
- pass rate и число повторных циклов;
- latency каждого узла и tool error rate;
- freshness, provenance и entity resolution;
- feedback cost explosion и доля зацикливаний.
