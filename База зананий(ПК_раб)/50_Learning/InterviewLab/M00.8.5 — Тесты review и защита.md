# M00.8.5 — Тесты, review и защита

## Результат задачи

Поведение подтверждено автоматическими тестами, код прошёл статические проверки, а архитектура объясняется без подсказок.

## Методология тестирования

Тестируйте наблюдаемое поведение и жизненный цикл, а не внутренние строки реализации.

Для каждого теста запишите:

```text
Given — исходное состояние
When  — действие
Then  — наблюдаемый результат
```

## Тест 1. Lifespan

```text
Given: приложение ещё не вошло в lifespan
When:  входим в with TestClient(app)
Then:  client существует и открыт
When:  выходим из with
Then:  тот же объект закрыт
```

Важно сохранить ссылку на объект до выхода, чтобы проверить именно тот же client.

## Тест 2. Переиспользование ресурса

Внутри одного `with TestClient(app)` дважды вызовите `/health/resources`.

Оба ответа:

- status code 200;
- `http_client == "ready"`.

## Тест 3. Успешная конкурентная диагностика

Вызовите endpoint с маленьким delay и достаточным timeout. Проверьте точный JSON-контракт, не полагаясь на точные миллисекунды.

## Тест 4. Timeout

Вызовите endpoint с timeout меньше delay. Проверьте:

- HTTP 504;
- понятный `detail`.

## Тест 5. Валидация

Минимум один невалидный query parameter должен вернуть 422 и не запустить service.
