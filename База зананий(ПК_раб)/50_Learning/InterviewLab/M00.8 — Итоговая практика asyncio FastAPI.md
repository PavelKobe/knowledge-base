## Часть A. Lifespan и HTTP client

Добавьте lifespan в функцию `create_app()`.

Требования:

1. До `yield` создаётся один `httpx.AsyncClient` с timeout 5 секунд.
2. Client сохраняется в `app.state.http_client`.
3. После `yield` client гарантированно закрывается.
4. Cleanup должен находиться в `finally` или в эквивалентном безопасном async context manager.
5. Создание приложения при импорте сохраняется: `app = create_app()`.

## Часть B. Dependency

- не создаёт и не закрывает client самостоятельно.

## Часть C. Resource health endpoint

Добавьте endpoint:

```text
GET /health/resources
```

Он получает client через `Depends` и возвращает:

```json
{
  "http_client": "ready"
}
```

Если client закрыт, состояние должно быть `closed`.

Endpoint не должен обращаться во внешний интернет.

## Часть D. Конкурентные проверки

Создайте модуль с двумя функциями.

Первая имитирует I/O:

```python
async def simulated_check(name: str, delay: float) -> str:
    ...
```

Она должна:

- использовать `await asyncio.sleep(delay)`;
- возвращать имя проверки;
- не использовать blocking I/O.

Вторая запускает две независимые проверки:

```python
async def run_checks(delay: float, timeout: float) -> list[str]:
    ...
```

Требования:

- использовать `asyncio.TaskGroup`;
- ограничить весь блок через `asyncio.timeout`;
- вернуть результаты обеих проверок;
- не подавлять cancellation.

Рекомендуемое расположение:

```text
src/interviewlab/services/diagnostics.py
```

## Часть E. Diagnostics endpoint

Добавьте endpoint:

```text
GET /diagnostics/async?delay=0.1&timeout=1.0
```

Успешный ответ:

```json
{
  "status": "ok",
  "checks": ["first", "second"]
}
```

Если общий timeout истёк:

- endpoint должен вернуть HTTP 504;
- detail должен понятно сообщать о timeout;
- `TimeoutError` преобразуется в HTTP-ошибку только на границе API, а не внутри `simulated_check`.

Валидация параметров:

- `delay` больше или равен нулю;
- `timeout` строго больше нуля;
- задайте разумные верхние пределы, чтобы учебный endpoint нельзя было заставить ждать слишком долго.

## Часть F. Тесты

Добавьте тесты минимум для четырёх сценариев.

### 1. Lifespan создаёт и закрывает client

Идея проверки:

```text
войти в with TestClient(app)
→ получить ссылку на app.state.http_client
→ убедиться, что client открыт
→ выйти из with
→ убедиться, что тот же client закрыт
```

### 2. Ресурс переиспользуется

В одном `with TestClient(app)` дважды вызвать `/health/resources`. Оба ответа должны быть `ready`.

### 3. Конкурентные проверки успешны

Вызвать diagnostics endpoint с достаточным timeout и проверить два результата.

### 4. Timeout превращается в HTTP 504

Задать `timeout` меньше `delay` и проверить status code и detail.

Не связывайте тест с чрезмерно точным измерением миллисекунд: на загруженной Windows-машине timing может немного колебаться.
