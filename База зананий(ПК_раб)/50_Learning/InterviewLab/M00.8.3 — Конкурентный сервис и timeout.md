# M00.8.3 — Конкурентный сервис и timeout

## Результат задачи

Чистый сервис запускает две независимые I/O-имитации конкурентно и ограничивает весь блок единым timeout.

## Что здесь тренируется

- coroutine;
- `TaskGroup`;
- конкурентность без threads;
- общий временной бюджет;
- распространение cancellation;
- отделение service layer от HTTP.

## Шаг 1. Реализовать одну проверку

Файл:

```text
src/interviewlab/services/diagnostics.py
```

`simulated_check(name, delay)` должна:

- использовать `await asyncio.sleep(delay)`;
- вернуть `name`;
- не знать о FastAPI и HTTP status codes;
- не ловить `CancelledError` без необходимости.

## Шаг 2. Реализовать orchestration

`run_checks(delay, timeout)` должна:

1. открыть один `asyncio.timeout(timeout)` вокруг всей группы;
2. открыть `asyncio.TaskGroup`;
3. создать Task `first` и `second`;
4. дождаться выхода из группы;
5. вернуть результаты после успешного выхода.

Не используйте:

```python
first = await simulated_check(...)
second = await simulated_check(...)
```

Это последовательная версия.

## Изолированная проверка без HTTP

Создайте временный scratch-файл IDE или Python Console и вызовите:

```text
run_checks(delay=0.1, timeout=1.0)  → успех
run_checks(delay=0.2, timeout=0.05) → TimeoutError
```

Не перехватывайте `TimeoutError` внутри `simulated_check`.
