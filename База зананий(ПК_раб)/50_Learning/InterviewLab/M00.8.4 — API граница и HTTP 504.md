# M00.8.4 — API-граница и HTTP 504

## Результат задачи

HTTP endpoint вызывает чистый async-сервис и преобразует технический timeout в понятный HTTP 504.

## Что здесь тренируется

- граница API и service layer;
- валидация query parameters;
- обработка ожидаемой ошибки;
- отсутствие широкого `except Exception`;
- семантика HTTP 504 Gateway Timeout.

## Шаг 1. Реализовать diagnostics endpoint

Каркас находится в:

```text
src/interviewlab/api/system.py
```

Endpoint:

```text
GET /diagnostics/async?delay=0.1&timeout=1.0
```

Должен:

1. вызвать `run_checks`;
2. при успехе вернуть status и список checks;
3. поймать только `TimeoutError`;
4. преобразовать его в `HTTPException(status_code=504, ...)`;
5. не скрывать неожиданные ошибки.

## Шаг 2. Добавить валидацию

Через FastAPI `Query` задайте:

- `delay >= 0`;
- `timeout > 0`;
- небольшие верхние пределы для обоих параметров.

Проверьте отрицательные значения: FastAPI должен вернуть 422 до входа в service.

## Ручные сценарии

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/diagnostics/async?delay=0.1&timeout=1"
```

Для просмотра 504 удобно:

```powershell
try {
    Invoke-RestMethod "http://127.0.0.1:8000/diagnostics/async?delay=0.2&timeout=0.05"
}
catch {
    $_.Exception.Response.StatusCode.value__
}
```
