8 архитектур RAG

Не «уровни зрелости», а разные паттерны retrieval. Выбирайте архитектуру по типу запроса, данным, качеству поиска и необходимой степени автономности.

01
🔎

Naive RAG

Для простых fact-based запросов

Базовый pipeline: вопрос превращается в embedding, из vector DB выбираются релевантные чанки, затем они подаются модели как контекст.

Query→Embedding→Vector DB→Context→LLM
Когда выбирать
  • FAQ и внутренние базы знаний.
  • Документы хорошо совпадают с пользовательскими формулировками.
  • Нужен быстрый MVP с минимальной сложностью.
02
🖼️

Multimodal RAG

Текст + изображения + аудио + таблицы

Retrieval работает сразу по нескольким типам данных. Полезно там, где смысл находится не только в тексте: схемах, фото, сканах, графиках и аудио.

Query→Multi-encoder→Multi-index→Text / Image / Audio→LLM/VLM
Когда выбирать
  • Инструкции со схемами и фотографиями.
  • Каталоги товаров.
  • Техническая документация с таблицами и диаграммами.
03
🧠

HyDE

Когда вопрос и документы «говорят разными словами»

Модель сначала генерирует гипотетический документ/ответ, затем embedding строится уже от него — это помогает найти реальные документы, семантически близкие к предполагаемому ответу.

Query→Hypothetical answer→Embedding→Vector DB→LLM
Когда выбирать
  • Пользователи сильно перефразируют терминологию документов.
  • Короткий запрос плохо совпадает с длинными документами.
  • Semantic retrieval даёт низкий recall.
04
✅

Corrective RAG

Когда retrieval нужно проверять

Полученные чанки оцениваются перед генерацией. Если контекст слабый, система переформулирует запрос, расширяет поиск или подключает другой источник.

Query→Retrieve→Grade→Rewrite / Web→LLM
Когда выбирать
  • Верхние top-k чанки часто выглядят релевантными, но не отвечают на вопрос.
  • Нужна проверка свежести или фактической опоры.
  • Есть несколько источников разного качества.
05
🕸️

Graph RAG

Когда ответ — это отношение между сущностями

Документы преобразуются в сущности и связи. Retrieval идёт через knowledge graph, что помогает отвечать на вопросы о зависимостях, цепочках и структуре.

Docs→Entities→Graph DB→Subgraph→LLM
Когда выбирать
  • Оргструктуры, зависимости систем, связи клиентов и транзакций.
  • Вопросы «как A связано с B?».
  • Нужен multi-hop reasoning по отношениям.
06
⚡

Hybrid RAG

Когда важны и смысл, и точные совпадения

Объединяет несколько retrieval-каналов: dense vector search, sparse/BM25, metadata filters и при необходимости graph retrieval. Результаты затем сливаются и rerank'ятся.

Query→DenseBM25Graph→Fusion + Rerank→LLM
Когда выбирать
  • Артикулы, номера договоров, имена и точные термины важны так же, как семантика.
  • Один vector search теряет точные совпадения.
  • Нужно повысить recall без перехода к агентной системе.
07
🧭

Adaptive RAG

Разные запросы → разные pipelines

Router оценивает вопрос и выбирает стратегию: ответ без retrieval, простой поиск, декомпозицию, multi-hop или специализированный retriever.

Query→Router→DirectSimple RAGMulti-step→LLM
Когда выбирать
  • Есть простые и сложные запросы в одном продукте.
  • Часть вопросов не требует поиска вообще.
  • Нужно контролировать стоимость и latency.
08
🤖

Agentic RAG

Когда путь к ответу заранее неизвестен

Агент планирует действия, решает какой инструмент вызвать, проводит несколько циклов retrieval, проверяет промежуточные результаты и завершает задачу по условию.

Goal→Agent / Planner↔SearchDBAPIFiles→Answer
Когда выбирать
  • Задачи требуют нескольких источников и инструментов.
  • Нужно уточнять стратегию по ходу поиска.
  • Есть сложные workflow: исследование, расследование, аналитика, действия через API.

Практическая стратегия внедрения

1. Начните с Naive RAG. Соберите end-to-end pipeline и набор эталонных вопросов.
2. Измеряйте retrieval отдельно. Recall@K, MRR/nDCG, качество chunking и metadata filters.
3. Добавьте Hybrid + reranker. Это часто даёт больший прирост, чем смена LLM.
4. Усложняйте только по сигналу. Graph, Adaptive и Agentic RAG нужны под конкретный тип ошибки или workflow.

Production checklist

Data: versioning, ACL, metadata, deduplication.
Retrieval: hybrid, rerank, filters, query rewriting.
Safety: prompt-injection defense, source trust, permissions.
Observability: traces, latency, token cost, retrieved chunks, feedback.
Evals: groundedness, faithfulness, correctness + retrieval metrics.
